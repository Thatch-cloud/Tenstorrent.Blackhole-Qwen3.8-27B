# P0.2 run plan — Achieved fabric bandwidth over four links

Generated by the fabric-tuning-cycle workflow. Audit verdict was VIOLATIONS
with eight findings; the framework fixes (candidate_at_least rule,
per-direction repeats keys) are already committed; the procedural corrections
are incorporated below.

## Tool command

`python optimisation/fabric-relay/fabric_bench.py --mode fabric --payload-mib
256 --repeats 9 --out artifacts/p02-fabric-<runid>.json` — rig host, pinned
runtime, invocation recorded verbatim. Note: the checked-in fabric copy path
raises NotImplementedError until the P1 harness lands. If it does, use the
tt-metal device-to-device NoC microbench with the identical
repeats/payload contract and record BOTH invocations verbatim plus the
fallback's source revision/hash; the artifact SHA256 cited must be the
fallback's output.

## Gates (all evaluated via gates.py; none skipped)

| Gate | Rule | Pass condition |
| --- | --- | --- |
| repeats_uni | at_least_repeats (key repeats_uni, 9) | ≥9 uni repeats at frozen payload; raw sample list in artifact |
| repeats_bidi | at_least_repeats (key repeats_bidi, 9) | ≥9 bidi repeats under identical conditions |
| fabric_ge_pcie_x4 | candidate_at_least (margin 0.0), four invocations | {uni, bidi} × {p50, p95} all ≥ P0.1 card-1 x4 baseline; p50 binding. **Higher-is-better rule — never pass raw GiB/s through candidate_not_worse_than.** |

A "fabric ≈ x4" pass still satisfies margin 0.0 (relay only wins during
load) — recorded as a nuance, never softening the margin. Any comparison
failure = phase REJECTED for relay admission with an explicit "do not
promote" line; P1 not admitted on fabric. The plan §4 DRAM-staging fallback,
if needed, is proposed as a NEW phase.

## Rig steps

1. Reset (if needed) via `~/.local/bin/tt-smi -r` from an interactive login
   shell (not on the non-interactive PATH; not `bash -s`/systemd); confirm the
   reset actually happened; links train at board init only.
2. Resolve cards by-id after any reset; record the by-id→device mapping.
3. After opening the mesh and before any copy, assert Logical and Physical
   intra-mesh degree histograms agree ({1:2}/{1:2}); Physical {0:2} aborts
   the run — the wrong-pair failure is silent.
4. Export `TT_MESH_GRAPH_DESC_PATH` (four-channel
   `p150_x2_mesh_graph_descriptor.textproto`); measure the link count via
   per-channel `test_system_health` / `get_num_links()`; record descriptor
   path and measured count. If only 2 links train, choose the descriptor from
   the measured count — do not proceed under the 4-link assumption.
5. Verify the rig is idle (no decode/CCL/verifier traffic sharing the four
   links); record the idle snapshot.
6. Confirm repo at the recorded immutable commit; confirm the P0.1 card-1 x4
   baseline record exists in `docs/` (run ID + artifact SHA256) — run P0.1
   first if not.
7. Run the uni leg then the bidi leg under identical conditions (one run
   set); freeze both artifacts (run ID + SHA256); all samples, outliers
   included, feed p50/p95 — no selective re-runs.
8. Evaluate gates; generate the record with `report_gen.py`; commit whether
   pass or fail.

## Record must cite

Experiment ID/date/owner/status; immutable repo commit; exact command/flags +
environment; separate run IDs for uni and bidi legs; SHA256 of each artifact
JSON; the cited P0.1 baseline (run ID, SHA256, card-1 x4 values); PCIe
topology, firmware, dispatch, confirmed measured link count + descriptor path;
per-repeat counts and p50/p95 for both directions; all gate outcomes with
evidence links; explicit decision line ("fabric ≥ x4 sustained" go/no-go) plus
the statement that no serving default changed and the relay remains opt-in
(`WEIGHT_LOAD_FABRIC_RELAY`, phases 1+); container/runtime/native-library
hashes; closure line (no runtime change, rollback not applicable, residual
device warnings recorded).

## Rejection conditions

- <9 completed repeats in either direction — reject; no best-of padding.
- Any fabric_ge_pcie_x4 invocation below baseline — reject for relay
  admission with do-not-promote line.
- Cabling/device identity not verifiable by-id — reject.
- Undocumented host round-trip or unlabeled card-0 DRAM staging — reject.
- Any statistic cited from a single winning run — reject.
- A direction metric missing without explicit justification — reject.
- Any phrasing enabling relay by default — reject outright.
