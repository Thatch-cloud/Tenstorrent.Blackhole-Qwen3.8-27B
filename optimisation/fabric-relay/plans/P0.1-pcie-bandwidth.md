# P0.1 run plan — Achieved PCIe bandwidth per card

Generated by the fabric-tuning-cycle workflow; audit verdict was VIOLATIONS
with six findings, all corrections incorporated below.

## Tool command

`python optimisation/fabric-relay/fabric_bench.py --mode pcie` on the rig host,
per block in scheduled order, cold cache per repeat; per-card read/write
bandwidth, ≥9 repeats, ABBA order (x16 card 0 vs x4 card 1).

## Gates

| Gate | Rule | Pass condition |
| --- | --- | --- |
| repeats | at_least_repeats (9) | ≥9 valid repeats per card per direction as distinct run IDs. All repeats — including outliers and stalls — are retained and reported; a repeat may be marked invalid with its reason, but its raw artifact and measurements stay in the per-repeat table. |
| ordering | abba_ordering | Fixed nine-block ABBA schedule frozen before execution (schedule hash recorded); arms are A=x16 card 0, B=x4 card 1 — the only arms admitted for P0.1. No reorder/skip/substitute. |

## Rig steps

1. If a reset is performed: invoke `~/.local/bin/tt-smi` by full path
   (not on the non-interactive PATH), verify the reset took effect (link
   state / re-enumeration observed), and after any re-cabling confirm links
   trained (non-zero) before measuring.
2. Resolve devices by `/dev/tenstorrent/by-id/blackhole-<serial>` **after**
   any reset, never before; record the by-id→device-number mapping snapshot.
3. Confirm cabling by **evidence, not assumption**: run `test_system_health`
   with `TT_MESH_GRAPH_DESC_PATH` set (without it the tool fails and prints
   nothing at v0.77) naming the expected peer, then assert Logical and
   Physical intra-mesh degree histograms agree after opening the mesh and
   **before any data transfer** — a mismatch (`{1:2}` requested vs `{0:2}`
   reality) is the silent cabling failure.
4. Snapshot host state; freeze matched-control context per
   winning-runtime-controls.
5. Fix the nine-block ABBA schedule in writing (schedule hash); never alter it.
6. Run the tool once per block; capture read_GiB_s, write_GiB_s, p50_ms,
   p95_ms per card; unique run ID per block; artifact SHA256 per repeat.
7. Evaluate gates in order with `gates.py` (repeats, then ordering); explicit
   pass/fail with evidence — no gate skipped.
8. Generate the record with `report_gen.py`; commit to `docs/` whether go or
   no-go; include a "do not promote" line if x4 is not load-limiting.

## Record must cite

Phase id; per-repeat run IDs with block index (1..9) and arm; card/link width;
direction with read/write GiB/s; p50/p95; artifact SHA256s; host snapshot;
schedule hash; cache state per repeat; gate verdicts; the decision (is card-1
x4 load-limiting); tool version/command line; timestamp and rig identifier;
repository immutable commit/tag; container/native-library hashes; CI run ID
and artifact location; SHA256 of the generated record itself. Cleanup /
residual warnings / rollback: explicitly "Not applicable (measurement-only;
no runtime or serving-default change)" — stated, not omitted.

## Rejection conditions

- Fewer than 9 valid repeats for any arm — re-run to full count; never
  extrapolate.
- Schedule deviation, reorder, skip, or substitution — reject.
- Warm cache or uncontrolled host I/O — reject.
- Device identity ambiguity or cabling not confirmed by evidence — reject.
- Any wording implying a serving-default or runtime change — reject at review.
- Gate evidence incomplete or a gate silently skipped — reject.
- Record missing run IDs, SHA256s, host snapshot, control context, or an
  explicit decision line — reject.
- Starting P0.2/P1 before this record is committed — reject.
