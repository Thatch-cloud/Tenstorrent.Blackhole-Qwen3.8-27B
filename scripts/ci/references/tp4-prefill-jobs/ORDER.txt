# The order of the tp4/prefill four-card window: the PREFILL measurement jobs and the adaptive Lever N governor's paired timing, on the tp4/next-2 stack (tp4/octo-2 + tp4/prod-fixes) plus this branch.
# One template per line: <template name without .env> <stop|soft> <image tag> <estimated minutes>.
# stop: the window halts at the first failure of this job. soft: a failure or a skip does not stop the window (dependents are skipped by the NEEDS lines below; every card job begins with a reset). Here only the build and the
#     status/rescan stop the window.
# WHAT THE WINDOW IS FOR (docs/tp4-profile.md 'Prefill profile', docs/lever-n-adaptive-governor.md):
#   PL1  the SOLO prefill ladder (one request at a time, nothing else running, so the Lever N governor paces nothing) at about 4k / 32k / 128k / 254k prompt tokens, and the same ladder with SEVEN short decoders running
#        (today's policy): TTFT and prefill tok/s per rung, busy over solo.
#   PP1  the prefill device op profile: ONE 131,072-token coding prompt = 64 prefill chunks of 2,048 tokens under tracy (op-support 20000), the profiler drained every 16 layers by the layer.py flush hook: per-op ms per chunk
#        at every context, the big matmuls' compute efficiency, attention prefill against context, the GDN chunked prefill (conv calls per chunk), glue and layout copies, collectives.
#   AD   the adaptive governor (QWEN_FAST_LEVERN_ADAPTIVE, default off, gate only): ABAB of the production profile against its gate-only twin on skew, 32k and a one-or-two-decoder long-prefill shape.
# P0. PRODUCTION: the owner stops the node agent and unserves production BEFORE X0 and restores it after Z (the cutover pack's steps and post-checks; nothing in this pack does either, and no job here starts or hands back the
#     agent). B0 is a build and may run while production serves. No other window driver may be alive and no privileged builder container up.
# P0. The CPU suite is green on the pushed tp4/prefill-1 head (gh workflow run qwen-cpu-suite.yml -f ref=<sha>) and the tag is pushed on THAT commit. Push ONE tag at a time and wait for its run to finish (the workflow keeps one
#     pending run; queued tags are cancelled). Never cancel a running card job, and NEVER cancel PP1 once its gate step has started (the profiler writes as root: a cancelled run leaves root-owned logs and the next checkout dies with
#     EACCES). No w2.off, levern.off, prefix-reuse.off or parked.off file on the hub mount.
# P0. TWO IMAGES: tp4-next2-1 (the integrated tp4/next-2 image, built by that window's B0) for X0, PL1, PP1 and Z, which measure the stack as it is; tp4-prefill-1 (a PLACEHOLDER for the tag B0 of THIS pack builds from the pushed head:
#     sed -i 's/tp4-prefill-1/<tag>/' *.env) for the AD arms, because the governor is image code. A commit of a file the image carries needs a new B0 build and a new tag in every template that names it. With the flag off the
#     governor image paces, decides and logs exactly as tp4-next2-1 does (a test compares the whole log), so A1 and A2 are the production profile on the new image.
# TIMED: PL1 and the four AD arms are timing jobs: the ARC runner sets are at ZERO for them (PL1 alone 30 minutes, the AD block about 160), no build and no CI push beside them. B0 never runs during them. X0, PP1 and Z are not timed
#     (PP1 is attribution; the ARC runner sets can be restored before it). Every result is UNQUALIFIED (the twin is gate only; the ladder and the profile are measurements, not gates).
