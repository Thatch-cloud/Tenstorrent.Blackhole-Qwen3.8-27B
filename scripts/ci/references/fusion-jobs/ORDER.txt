# The order of the op-fusion programme's four-card DEVELOPMENT window (docs/tp4-fusion.md): ONE image (tp4-fusion-1, built by B0 from tp4/fusion-1 = tp4/next2-1 + the merged work packages) and ONE window for the
# fused-op arms of the packages, each behind default-off flags: S1 shard argmax (WP1: QWEN_FAST_TP4_SHARD_ARGMAX=1); K/V page writer (WP2: QWEN_FAST_KV_PAGE_WRITER=1); MLP streaming config and L1 multiply (WP4: QWEN_FAST_MLP_CFG=l1); CCL options (WP5: QWEN_FAST_CCL_OPTIONS=rs-c1); WP6 F-F1 drafter local reduce (WP6: QWEN_FAST_DRAFT_REDUCE=1); WP6 F-F3a drafter SwiGLU and residual kernels (WP6: QWEN_FAST_DRAFT_TAIL=1); WP6 F-F3c drafter fused gate|up matmul (WP6: QWEN_FAST_DRAFT_GATEUP1=1, QWEN_FAST_DRAFT_TAIL=1); WP6 R2 drafter matmuls on device-width grids (WP6: QWEN_FAST_DRAFT_MM_GRID=1); F-F2 drafter permutation kernels (WP7: QWEN_FAST_DRAFT_PERMUTE=1); F-F3c fused drafter q|k|v projection (WP7: QWEN_FAST_DRAFT_QKV1=1); F-F4 one 64-row drafter head (WP7: QWEN_FAST_DRAFT_HEAD64=1); WPH-1 pre-stage diff (WPH: QWEN_FAST_PRESTAGE_DIFF=1); WPH-2 lean write_packed (WPH: QWEN_FAST_WRITE_PACKED_LEAN=1); WPH-3 batched verify and collect read-backs (WPH: QWEN_FAST_BATCHED_READS=1); MLP fused gate|up with SwiGLU epilogue (WP4: QWEN_FAST_MLP_GATEUP=1).
# One template per line: <template name without .env> <stop|soft> <image tag> <estimated minutes>. The minutes are generic ESTIMATES (nothing has run on a card): a package's own folder has its own.
# stop: the window halts at the first failure of this job. soft: a failure or a skip does not stop the window (a lever's timed jobs are skipped by the NEEDS lines below, the other levers still run).
# P0. PRODUCTION: the owner stops the node agent and unserves production BEFORE X0 and restores it after Z (the cutover pack's restore steps and post-checks; nothing in this pack does either, and no job here starts or
#     hands back the agent). B0 is a build and may run while production serves. No other window driver may be alive and no privileged builder container up.
# P0. The CPU suite is green on the pushed branch head (gh workflow run qwen-cpu-suite.yml -f ref=<sha>) and the tag is pushed on THAT commit. Push ONE tag at a time and wait for its run to finish (the workflow keeps one
#     pending run; queued tags are cancelled). Never cancel a running card job.
# P0. CI PAUSED: the owner scales the rig's ARC runner sets to zero from the first timed job to the last (CI shares the host and skews round times; the hardware host runner that runs these jobs is NOT scaled down) and restores
#     them after it. The load average is read with every pair (w2ln_timing_compare.py load-limit).
# P0. GRID: the four cards expose a 13x10 compute grid since the firmware unlock. Read it from the run (AVAILABLE WORKER CORE COUNT), never assume 11x10: every pair runs on one grid, and a number from an 11x10 run is not this pack's control.
# Every result is UNQUALIFIED (gate-only twins of the production profile; the control is the production profile itself, which carries an owner traffic waiver). A lever that passes its audit and its ABAB is a go to
#     confirm it in the ship profile, not to ship. Each twin is the production profile plus exactly one lever (and, for the audit twin, its _AUDIT flag): make_fusion_profiles.py generated it from the package's manifest.
# THE JOBS OF A LEVER <ID>: <ID>A the audited attach (exactness: the lever's served-composition comparison in the trace), then the timed ABAB at eight live (concurrent8_steady): <ID>C1 control, <ID>L1 lever, <ID>C2 control, <ID>L2 lever.
#     The audits of every lever run before any timed pair, so a lever that is not exact costs one short job, not an hour of timing.
# THE PACKAGES' OWN FOLDERS (card-M and detail templates, their read rules and decision rules; under references/): fusion-jobs-wp5, fusion-jobs/M1, fusion-jobs/TEL, fusion-jobs/WP1, fusion-jobs/WP2, fusion-jobs/WP4, fusion-jobs/WP6, fusion-jobs/WPH, fusion-wp7-jobs.
# THE COMBINED PACK (references/fusion-jobs/combined: c2-packed-tp4-8x262k-ship-prefix-levern-w2-er-fx-all, the levers permute, s1, reduce, qkv1, tail, gateup1, mmgrid, head64, ccl, mlpcfg, kvpage, prestage-diff, lean, reads on together; its own ORDER.txt) runs FIRST; this ORDER is the ablation, for the levers of a combination that fails.
# THE SHIP PACK (references/fusion-jobs/ship: B0 G1 GX0 GX1 G2 SR for the traffic profile c2-packed-tp4-8x262k-ship-prefix-levern-w2-er-fx-traffic under the owner traffic waiver w2-er-fx-262k-2026-10-11, PENDING until the owner approves; its own ORDER.txt) runs AFTER the combined window passes, not before it.
# FOLDED IN: UP* are the templates of references/upload-p0-jobs (WP0), renamed and on the one image; their read and decision rules are that folder's ORDER.txt. tp4/upload-p0: the engine-start levers QWEN_FAST_DEVICE_ZEROS and QWEN_FAST_LAZY_SHARD_W (exactness A0-A3, then the engine-start ABAB T0-T5 read with engine_start_phases.py, which can run anywhere in the timed block).
# LAST: MLPGU (MLP fused gate|up with SwiGLU epilogue) runs after every other arm, audit and ABAB alike: F-D1's fused kernels have never compiled on a card: run the card-M job C3 (fusion-jobs/WP4, the product against the served multiply, bit for bit) first, and these four-card arms last, so that a compile failure or a differing product costs the least of the window.
