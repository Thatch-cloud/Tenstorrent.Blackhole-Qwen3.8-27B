# <template name without .env> <class> <image tag> <estimated minutes> <tag> <box minutes>.
# CLASSES. stop: the extension halts at its first failure (the hand-back still runs). soft: data; a failure or a skip does not stop it. hand: the hand-back, always runs once the extension took the cards. drv: a DRIVER or OPERATOR step with no template and no tag (LM: the links re-measure workflow; TICK: the wait for the topology to publish the new links; DEPLOY-and-engine-load: the operator's release step and the engine load).
# VALUE ORDER (the jobs the production go-live skipped, most valuable first, the smoke and replay jobs that can hang come early, and T0 sits ahead of G0 so a hung T0 never delays a gate job's slot: E1-CTL is NOT moved behind T0 because under the box rule E1-CTL (box 153) then no longer fits): A0X0 (the cards, no status step), H1 and H2 (the production hang shapes), SR10 (the platform replay of the production thin layer), C16-CTL (churn at eight seats), E1-CTL (eager exactness to 262k), T0 (the timed production-bytes round), G0 (agent turns, timed). # MINUTES are MEASURED-BASIS ESTIMATES (the fast-window plan's measured job times): attach 2-5 min, reset 0.7-4.4 min, the five-shape smoke jobs 9-18 min, the hang jobs 11.5-16.1 min, a G arm 16.5 min, SR10 about 25 min, a T job 25-31 min, E1 60-153 min, C16 20-35 min; A0X0 is a stop, a rescan and a reset (10).

# BOXES are the ADMISSION worst case, not a cancel time (a started job is never cancelled): twice the measured worst for a smoke job (H1 and H2 35, T0 65), for C16-CTL (70) and for G0 (40), SR10 120 (its own thinking-budget smoke is up to 90 min), and E1-CTL 153, the gate's own timeout (c2_prefix_gate PLAN_ARMS: computed by test_tp4_baseline_ext_window). The gates' own timeouts for C16-CTL and G0 are 153 min; the workflow's own step caps (smoke 210 min, replay 180 min) are higher than every smoke box. A '-' box is a short step with no gate timeout.
# THE HAND-BACK IS 95 MIN: the reset 15 + the links re-measure 15 + the wait for the topology to publish the new links up to 18 (these three, 48 min, end at READY FOR /deploy) + the agent start Z 32 + the release step and the engine load 15 (these two come AFTER READY: the operator releases during Z's wait, minutes after READY). The 95 is for reporting only; the clock rule below uses the 48.
# THE CLOCK RULE (the private driver, a WALL-CLOCK rule against READY FOR /deploy and not an elapsed budget): with NOW the wall clock and HA the READY lead (ZR + LM + TICK = 48): a job starts only if NOW + its ESTIMATE + HA <= the READY TARGET (19:45Z, 08:45 NZ) AND NOW + its BOX + HA <= the HARD CAP (20:00Z = 09:00 NZ, the end of the owner's stated window for the operator's /deploy: the READY worst case if every admitted job takes its whole box); a job with no box uses its estimate for both; else it is SKIPPED-TIME. The same dual rule as the first window. Nothing is ever cancelled. The driver does not start before the first window's hand-back reached READY FOR /deploy (its START GATE), and it takes the cards only when production is NOT serving (a container or an answering endpoint after the first window's READY means production was released: the extension then halts and touches nothing).
# STOP-EARLY: the driver reads a file named STOP in its results directory before the start gate opens (a clean exit, no card touched) and before every job (it skips the rest and runs the hand-back, if the extension took the cards).
# TAGS: experiment/c2-serving-v601 to v615, hardware-allowlisted and never pushed (the driver checks the remote with ls-remote before it takes the cards). The k-th job that has a tag takes the k-th tag of v601 upward; the reserve v611-v615 is for a retried ZR or Z (the driver uses v611 and v612). The first window uses v538-v557 and another plan may use v558 upward: this block stays inside v601-v615. SR10's tag is deleted from the remote after its run (its commit names the production thin-layer image).
# NO OTHER WINDOW DRIVER MAY BE ALIVE and no privileged builder container may be up. The driver checks, before it takes the cards: no runs/*/.driver.lock of the generalised window driver, no other hwchain, window-driver or gen4 process, no queued or running qwen-c2-serving run. Every job that opens a gate, prefix or smoke step refuses to start while prefix-reuse.off or levern.off exists on the hub mount (the workflow's preflight step).
