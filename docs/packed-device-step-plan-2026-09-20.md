# Plan: `packed_device_step` as a drop-in for `sequential_packed_step` (2026-09-20)

Read-only survey of the worktree `t32-score-reuse`; all paths under `scripts/ci/` unless noted. Goal context: 200 tok/s per user for four concurrent users; today two users decode correctly end to end (run 35490298652) through `serving_sequential_step.sequential_packed_step`, one full pass over the 19.92 GB of dense weights per user per round.

**Interface and milestones.** Same signature and contract as `serving_sequential_step.sequential_packed_step` (serving_sequential_step.py:50-73): entries in scheduler order, one `CommittedOutput` per entry, same order; injected at serving_runtime.py:143-147. Milestone M1 = two T16 users in one 32-row block; M2 = four T8 users (same block, `packed_geometry(4)` at serving_fast_policy.py:35-43); M3 = four T16 users at 64 rows. Every shape-dependent choice below is keyed on a `PackedShape(users, rows_per_user, block_rows, page_width, capacity)` so M2/M3 add captures, not code paths.

## 2. Assembling the 32-row verify and getting prefixes back out

- Eligibility: every entry's ticket has exactly `rows_per_user` tokens (greedy_session.py:79 narrows tickets when `remaining < 16`) and `len(entries) == users` of a captured shape; otherwise `packed_device_step` delegates to `sequential_packed_step` for that round (`build_pack` refuses anything but an exact block, verifier_pack.py:58-60). N=1 (survivor after a finish) also takes the sequential path.
- Participants in ENTRIES order: `verifier_pack.participant(engine, 16, prefix=0, checkpoints, slots)` (verifier_pack.py:22-32) with `slots = engine.carry` (pooled `VerifierSlot.carry`, serving_buffer_pool.py:124-131, borrowed at verifier_engine.py:349-361) and `checkpoints` = the block's own per-user checkpoint sets; `build_pack(..., block_rows=32)` (:53-65) -> `ModelBatch(pack=...)` (model_batch.py:26-56, :303-309); positions/pages per row from `target_packed_pages.packed_rows` (target_packed_pages.py:66-81), per-row page tables at model_batch.py:136-137. Segment u = rows `[16u, 16u+16)` <-> `entries[u]`.
- Per step: `stage_packed_inputs` (new) writes tokens (32,1), per-user positions, cos/sin, singleton positions, the `pages` rows and `row_pages[16u:16u+16]` from `entries[u].request.engine.pages` (host copy kept current by `refresh`, serving_page_binding.py:106). `stage_inputs` cannot be reused: it builds one arange from one `start` (verifier_inputs.py:18, :37) and never restages pages.
- Readback: `sample_rows` at 32 rows is supported (force_argmax.py:9-15); host ids reshaped `[:32]` (verifier_engine.py:446-448) -> `predictions[16u:16u+16]` per user.
- Commit per user, in entries order: `session.commit(request_id, ticket_u, predictions_u, runtime_u.publish)` (greedy_session.py:91-114 computes `decision.state_rows` = accepted prefix). Output = `CommittedOutput(request_id, tuple(decision.emitted), session.position, session.finished)` (serving_fast_request.py:8-14, :84). Cancellation mirrors serving_fast_request.py:53-59 and :66-69 (`session.abort` -> `publish(0)`).
- To let `runtime.publish` run unchanged (it demands `engine.phase == 'verified'` and `engine.pending is ticket`, dflash_request_runtime.py:56-58), add `VerifierEngine.adopt_packed(ticket, block, segment)` that sets phase/pending/`pending_key` to a synthetic bucket whose `feature_capture.outputs()` is the block's 32-row taps and whose `publish(prefix)` calls `block.commit_user(segment, prefix)`, then `self.position += prefix`, phase idle, and skips `save_carry`. `project_features` gains `row_offset=` (dflash_device.py:532-550 slices rows `[0, count)` today).

## 3. GDN carry in the packed step

- Today: host-fenced pair `restore_carry` before the trace (verifier_engine.py:386-396, `[CARRY]` lines :372-384) and `save_carry` after commit (:398-402), with residency in the module global `_resident` (:19, :22-25).
- Packed: `DeviceLoopState.decode(segments=, slots=)` (gdn_device_loop_state.py:93-118) runs `_project_qkvzab_raw` once over 32 rows (:140), then per segment `active.restore(slot_u)` (:148), a device copy (gdn_snapshot.py:35-39) CAPTURED INSIDE the verify trace, then the recurrence on the slice (:149-151). The restore is therefore free of host fences and the slot addresses are pooled and fixed.
- Save is replaced by the commit DMA writing straight into the user's carry: `gdn_commit_dma.prepare(mesh, layers_u, prefix_u)` (gdn_commit_dma.py:22-71) with `layers_u = [*entry_u, states_u(16,24,128,128), *packed_conv_states_u, rec_state, *conv_states, *carry_slot_u]`; the carry has the compact checkpoint shape the kernel already expects (validate_shapes :12-14; `helper.allocate()` shape, verifier_pack.py:37-41). Native slot 0 is written as a side effect; set `verifier_engine._resident = None` after every packed step so a later sequential step of any user restores first (verifier_engine.py:389). `prefix_u == 0` must be a no-op on the carry (skip the DMA).
- Required changes in `_decode_packed`: it refuses `commit_only` (:138-139), restores the prefix EAGERLY at decode time (:153-155) with prefixes known up front, and keeps ONE `entry` per layer overwritten by each segment (:63, :72). Add a deferred mode: per-segment `entry`, no restore at decode, `segment_results` kept (:165-167) for a `commit_user(u, prefix)` on a packed retained block (gdn_records.py:58-83 takes one int prefix; `append` demands `states.shape[0] == rows` at :40, but the packed combined result carries segment 0's states, gdn_device_loop_state.py:165).
- The pack's hazard (:158-161) is contained: within the packed engine every segment restores its own slot; the sequential fallback restores via `restore_carry` because `_resident` is cleared.

## 4. Traces, captures, lifetimes, shape enum

- Not reusable: every per-request verify bucket (16-row fixture, one page table repeated, one start, replay reader at one family, 16-row taps, commits into native slot 0: verifier_engine.py:184-278, attention_replay.py:25-56) and every per-request commit trace (:264-273, prefix baked at gdn_commit_dma.py:63).
- New captures per shape (M1: one shape): one 32-row verify trace (ModelBatch `retain_records=True`, `commit_only_gdn=False`, `attention_replay=False` so the per-row `SerialAttentionReader` uses `singleton_positions`/`row_pages`, attention_batch.py:82-105; `target_attention_t16=False` because the gate pins `rows == 16`, target_t16_attention_gate.py:25-29 and frozen_combined_runtime.py:58 via frozen_combined_adapters.py:55) plus `users x (rows_per_user + 1)` commit traces (34 for M1).
- Lifetime rule (serving_buffer_pool.py:1-58): allocate the packed engine at attach AFTER the pool (serving_runtime.py:76-79) and AFTER `PreparedDraftWeights` (:104-105), BEFORE the lifecycle (:145); everything it keeps (32-row inputs incl. 32 row tables, 5 taps (1,1,32,5120), 2x48 checkpoints, per-layer `entry`/`state`) is then pre-trace by construction, so M1 needs no `PackedSlot` in the pool; add one when shapes multiply (M2/M3). Per-request engines still capture their own buckets after it and stay valid (their persistent buffers are pooled, docs :1091-1112).
- Shape enum: `(users, rows_per_user, block_rows, page_width, capacity)`; M1 `(2,16,32,pw,pw*64)`, M2 `(4,8,32,...)`, M3 `(4,16,64,...)`. The serving context pin (position 32768, budget 256) makes one replay family cover the whole decode (attention_mask_replay.py:13-31), which is what makes a per-user `ReplayAttentionReader` (rows=16, start_u, pages_u; attention_replay.py:13-56) capturable at attach as M1b.
