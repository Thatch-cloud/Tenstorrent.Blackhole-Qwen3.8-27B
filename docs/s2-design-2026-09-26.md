## 1. Summary and end state

### 1.1 What S2 does

Today the M3 block serves a round only when every live frontier sits in one 256-key family, [131072, 131312]. Two things enforce this:
- the pinned `validate_ticket` (`attention_mask_replay.py:26-32`), which the staged copy lifts only for the selected capacity (`frozen_target_replay.py:183-191`);
- the compile-time `cur_pos` of the replay SDPA (`attention_parallel.py:17-19`: no `cur_pos_tensor`).

The `c2` profile therefore builds no block at all (`qwen_c2_profiles.json:75-76`, `serving_runtime.py:255`). Every 4-live round is sequential, at 7-10 tok/s per user (MEM goal-c2-serving.md:20).

S2 makes the block serve 2-4 live users at any position ≥ 128, each at its own extent E = (start//256+1)·256. It has ten parts:

1. **K64j flag 0x20** (qualified: CB1 PASS, §1.4 #11). Each bundle takes its extent from a per-bundle `cur_pos` tensor holding E−1 ([k64j] `optimisation/ttnn-op/k64j/apply_factory_k64j.py:95-117`).
2. **New extent readers,** written beside the pinned ones and never subclassing them. They take a pool-lent full-width table and a `cur_pos` per bundle, plus a narrow (B,1,96,256) tail mask. They stage all three at construction [A6], and keep the pinned reader's G8 precondition [B7].
3. **The narrow mask comes from the pinned kernel,** run at capacity 256 with a relative start word, so no new kernel is needed (§2.3).
4. **Block and step.** Family checks become capacity checks. A boundary cap accepts at most E−start rows. Idle segments become ordinary users at E=256 on the zero table. New: an in-run **extent audit** on the gate profiles [A1], a gate-only capture-position knob for G3b [B1], and a replay deadline [B5].
5. **Memory.** Under the extent flag only [A5], per-request engines build one 2048 proposal bucket. A **scheduler-side DRAM admission hold** keeps a prompt waiting instead of letting its prefill or engine build run out of DRAM [B4]. Dead pair and quad traces are released when their request detaches [B3].
6. **D1 survivor narrowing** in place of `refuse_round` (PLAN:450-453). New: the residual `refuse_round` finishes its requests as FINISHED_ABORTED through the D2 quarantine instead of killing the engine one step later (W5b) [B2].
7. **Image and profiles.** Graft K64j replaces K64i. New profiles `c2-packed` and `c2-packed-gate`. An attach-time admission module with evidence pins.
8. **Exactness policy** [A1, B1]. The user's standing default stays: concurrent == solo, and a reproduced divergence FAILS (MEM goal-c2-serving.md:35). It is made decidable by a decisive card-B K2 test. The design no longer relaxes it on its own; if K2 fails, the relaxation goes to the user as decision D-c (§6.1).
9. **Same-path oracles below C** [A1, B1]: G3b (flag off against flag on at families 4352 and 16640) and the extent audit.
10. **Gates,** reordered [B2]: card-B kernel sections first (K2, 0x7 narrow==wide, the 15 small families), then the reader harness, then M+A with lifecycle before the G4 matrix and a G5 churn arm [B3, B8, B9].

### 1.3 A round for 1-4 live users

The rule for which rounds are packed stays all-or-nothing (`serving_packed_step.py:24-31`).

**Eligibility.** A round is packed when every live request is:
- bound to a segment;
- at a position with 128 ≤ position and position+16 ≤ 131328;
- holding ≥ 16 tokens of budget (`serving_packed_step.py:229-230`);
- passing the padded rules (`packed_verifier.py:957-985`) and the T2 tile-row check (`serving_packed_step.py:391-392`).

| Live | Path | Segments | Per-user decode |
|---|---|---|---|
| 4 | One packed verify | 4 live, each at its own E; one bundle each at G8 (flags 0x27) | 27-35 tok/s (e, PLAN:548-552) |
| 3 | Packed, padded | 3 live, 1 idle at start 0 on the zero table (E=256) | 28-31 at 131k; up to ~37 short (e, PLAN:553-554) |
| 2 | Packed, padded | 2 live, idle at starts 0 and 32 (page 0, tile rows 0 and 1) | As above |
| 1 | Sequential 4-row engine (`PADDED_MIN_USERS_DEFAULT=2`, `packed_verifier.py:396`) | None | 22-33 (PLAN:555); S3 packs lone users |
| Any, if one live user fails eligibility | Whole round sequential | None | S1 rates for that round |

In every packed round, each user's commit is capped at `accept_limit = min(16, E−start)` rows (§2.4).

## 2. Round anatomy

### 2.1 What changes per round, and who writes it

These are per chip (both chips are replicated). The values come from one `packed_values` call (`packed_verifier.py:254-313`) and are copied by `write_packed` (`:316-349`; addresses are checked unmoved, `:327`, `:342-343`). Under `QWEN_FAST_PRESTAGE=1`, everything except the tokens is written in the drafts' window without a fence, and the verify writes only the values that differ (`verify_prestage.py:217-238, 268-285`).

**Unchanged from today**

| Input | Shape | Writer | Changes |
|---|---|---|---|
| tokens | (64,1) uint32 | Host, at verify only (the prestage excludes them, `verify_prestage.py:229-231`) | Every round |
| positions; cos/sin; 64 singleton positions | (64,), tiled bf16, (1,) | Host | Every round |
| pages; 64 row tables | (64,2052), (1,2052) int32 | Host | On a vLLM page append or a user change |
| Per 32-row tile: K/V positions and pages | (32,), (32,2052) | Host | Every round / on append |
| Per segment, per bundle: replay page table | (2,2052) int32, the user's table repeated (`:308`) | Host into pool-lent tables | On append or user change. The shape equals today's C-family table (C//64 = 2052). |

**Changed by S2**

| Input | Shape | Writer | Changes |
|---|---|---|---|
| Per segment: mask word | (8,) int32, reader-owned. word0 = start & 255 (today: absolute start, `:305-306`) | Host | Every round |
| Per segment, per bundle: `cur_pos` (new) | (2,) int32 row-major, DRAM interleaved, pool-lent; both slots E−1 | Host | Only when E changes: a 256-boundary crossing (about every 50-56 rounds per user (e) at 4.5-5 tokens per round, PLAN:546), admission, or a live↔idle switch |
| Per segment, per bundle: narrow mask (new width) | (2,1,96,256) bf16 TILE, reader-owned | **Device:** the pinned mask kernel in-trace, once per forward under mask_once (`model_batch.py:838-843`) | Every round |

**Idle segment j.** start = 32·(j%2), so word0 = 0 or 32, `cur_pos` = [255, 255], a zero table, and tokens (1,)×16. It lands on page 0 tile row j%2, exactly as today (`packed_verifier.py:1012-1015`).

Word0 and `cur_pos` come from **one** helper, `extent_values(start)`, in the same `packed_values` call, so they cannot disagree. **Construction** stages the same three values (word, `cur_pos`, tables) for the reader's initial start, fenced and address-checked, as the pooled reader's `stage_pages` does ([k64j] `pooled_attention_replay.py:339-355`) [A6]. Without that, the pool's zeroed `cur_pos` (`serving_buffer_pool.py:446-455`) would describe E=256 while `reader.start` says C−256, and `model_batch.py:613-614` skips the initial `stage` exactly when `reader.start` already equals the capture start.

### 2.2 Order relative to the trace replay

1. **Commits of round r−1 finish**, so every frontier is final. Commits are `commit_entry` per user, then `block.commit_user`, with the last one fencing (`serving_packed_step.py:697-797`; `packed_verifier.py:1277-1347`).
2. **Drafts for round r are enqueued:** quad/pair/single traces (`serving_worker_hook.py:431-552`; coordinator `:388-587`). Then comes the window.
3. **Prestage:** `BlockPrestage.prestage` → `packed_values(guard=False)` → `write_packed(fence=False)` for every non-token input, including the new words and `cur_pos` (`verify_prestage.py:208-238`).
4. **Fence F9.**
5. **Verify:**
   - host checks: `admits` for each live ticket, then the padded refusal (`packed_verifier.py:1017-1055`);
   - the prestage diff writes only changed values (`verify_prestage.py:254-285`), or a full `stage_packed` if the epoch moved;
   - `note_packed_step`;
   - `execute_trace` on CQ0 (`:1081`), under the replay deadline (W3, [B5]). The copies are ordered before it on the in-order CQ0.
6. **Inside the replay:**
   1. `shared_masks(16)` runs each segment's mask program once. At G8 that is 4 launches, as today. The kernel reads word0 and writes all 8 column tiles of the narrow mask (`attention_mask_replay.cpp:13-33`).
   2. Then, in each of the 16 full-attention layers:
      - the K/V write (chains per user under T2);
      - per segment: a DRAM slice of its 16 rows (as `[k64j] pooled_attention_replay.py:510-514`);
      - per bundle: fold (`device_layout_dma`), then SDPA with sentinel `0x51DEC000|0x27`, the bundle's `cur_pos`, the narrow mask, the full-width table, `is_causal=False` and `k_chunk_size=256`;
      - unfold, then concat.
7. **Extent audit** (gate profiles only, `QWEN_FAST_EXTENT_AUDIT=1`) [A1]. After the replay returns, it reads back from both chips every segment's word and `cur_pos`, and in rotation one segment's narrow masks and full-width tables. It compares them with `extent_values(start)`, the host transliteration of `attention_mask_replay.cpp:18-33` at capacity 256, and the host table. It logs one `[EXTENT-AUDIT] round= segments= words_ok= cur_pos_ok= mask_ok= tables_ok= ms=` line per packed round. A mismatch logs `[EXTENT-AUDIT] MISMATCH …` and restages the round in full, as PRESTAGE_AUDIT does (`verify_prestage.py:306-337`). The gate fails the arm on any mismatch line, and on an audit-line count below the packed-round count.
8. **Readback.** Idle segments commit at prefix 0 first (`:1135-1141`). Then each live `commit_entry` runs with `max_rows = accept_limit(start)`.

### 2.3 Why each segment equals the per-family compile-time call, byte for byte

For a live segment at start s (128 ≤ s, s+16 ≤ C), E = (s//256+1)·256, rows not crossing E:

1. **Layout.** `LAYOUT = parallel_groups(256, 16, max_group_rows=8)` gives one B=2 bundle (offsets 0, 8).
   - For every s ≥ 128, all rows of a non-crossing ticket share the chunk signature (256, E) (`attention_head_fold.py:32-63`).
   - So the pinned reader captured at s would bundle identically.
   - Rows below position 128 have 128-key native chunks (`attention_head_fold.py:40-41`), hence the floor.
2. **Mask content.** Write o(h) = offset + b·rows + (h mod 6·rows)/6.
   - The pinned kernel at capacity E with word s writes −inf where E−256+32ct+c > s+o(h) (`.cpp:24,27-28`), into tiles `(b·HT+ht)·(E/32) + E/32 − 8 + ct` (`:32`).
   - Since E−256 = s − (s&255), the predicate is 32ct+c > (s&255)+o(h).
   - At capacity 256 with word s&255 the predicate is identical, and the page is `(b·HT+ht)·8 + ct`: the narrow tensor's tile (b, ht, ct).
   - So **narrow = the last 256 columns of the pinned wide mask at E**. At rows=8 there are no padding heads (`h < 96 = 12·rows`, `.cpp:28`).
   - The wide mask is +0.0 elsewhere (zero upload, `attention_replay.py:51`; the kernel writes only the last 8 tiles). The narrow tensor is rewritten whole on every replay, so no tile carries over.
   - Tail mode reads only the final chunk (`[k64j] pooled_attention_replay.py:61-64`; `[k64j] k64j/kernels/dataflow/reader_decode_qwen_slice.cpp:340`).
3. **Split.**
   - Under 0x20 the reader, compute and writer read `cur_pos` from the tensor (R10/C3/W4, [k64j] `k64j_probe/README.md:299-305`).
   - The split depends only on `nearest_n(cur_pos+1, 256)` (README:53-58, all 513 families checked by SplitModelTests), so `cur_pos = E−1` gives the capacity-E split, which is also the compile-time `St·32−1` of a capacity-E call.
   - Cores per head depend on B (README:61-62), and B is fixed by the layout.
   - Share: both slots carry E−1, and R10 copies slot 0 anyway (README:241-243).
4. **Keys read.** Only table columns [0, E/64) are read. P0's poisoned pages past E and K1's fence trace prove it on hardware (`[k64j] k64j/k64j_card_b.py:31-35`; MEM goal-c2-serving.md:24, trace 144/144 in CB1).
5. **Kernel equality: what is proven, and the one gap** [A2].
   - K1 (CB1 PASS): 0x21/0x23/0x27/0x2F at `cur_pos = E−1` on the C-wide table with the narrow mask == the same flags minus 0x20 at capacity E **with the same narrow mask** (`[k64j] k64j/k64j_card_b.py:10-12`).
   - Card M: narrow == wide under tail (0x1) and tail+share (0x3) only (`[k64j] optimisation/ttnn-op/sdpa_decode_qwen/README.md:156,160`).
   - P0 section E ran 0x7 against a wide mask only at the all-visible position E−1 (`zero=True`, `[k64j] k64j_probe/probe_k64j_card_b.py:766-775`).
   - **So 0x7-narrow == 0x7-wide with a real −inf tail is unproven.** A narrow-mask indexing error in the K64i slice reader (`mask_batch_offset`, `reader_decode_qwen_slice.cpp:338-341`) would be shared by 0x27 and 0x7-narrow, and K1 could not see it. CB2a X7 closes it at five families × five starts (§6.2), and CB2b R2 closes it again through the reader classes, against 0x7 with the **wide** −inf mask.
6. **Fold/unfold.** `execute_extent` is `attention_parallel.execute` (`:6-30`) with one added argument, `cur_pos_tensor`. `device_layout_dma` is imported unchanged.

At E = C = 131328 (G3), items 1-6 reduce to v235's served call except for item 5's gap: flag on runs 0x27 with the narrow mask where v235 ran 0x7 with the wide one. G3 must therefore be **identical to v235**, and it is the model-level check of X7 at C. G3b (§6.3 M5) is the model-level check below C.

### 2.4 Rows past E: the boundary cap

When s&255 > 240, rows at positions ≥ E have (s&255)+o(h) ≥ 256, so the relative predicate is false for every column. They see **all of [0, E)**, since tail mode masks only the final chunk (`reader_decode_qwen_slice.cpp:340,451`), and never their own key [A7]. Their outputs are wrong by design.

`accept_limit(s) = min(16, E−s)`:
- `GreedySession.commit(max_rows=L)` evaluates `select_prefix(tokens[1:L], predictions[:L])`. That keeps K+1 = L predictions (`greedy_verify.py:14-41`), so emitted ≤ L and `state_rows` ≤ L.
- The rows that pass the cap are exactly the valid ones: prediction[i] for i < L comes from a row at position < E.
- Capped rows are handled like rejected drafts: their K/V lies past the committed frontier, and GDN commits at the prefix (PLAN:431-434).
- **The session cap is the primary control** [A8, B10]. The block backstop (`commit_user` refuses prefix > L for the segment's staged start) sits with the host checks **before** `commit_user`'s `try` (`packed_verifier.py:1291-1300`, the `try` at `:1310`), so a refusal does not also set `phase='failed'`. Any firing still fails every request of the round and re-raises (`fail_round`, `serving_packed_step.py:534-536,817-842`), which is an outage. So W4 adds a property test that the backstop is unreachable: for every s and every predictions vector, `state_rows ≤ accept_limit(s)`.
- Frequency: the cap applies in 15/256 ≈ 6% of a user's rounds (d) and costs ~1% of tokens (e, PLAN:434).

## 6. Hardware gate plan

### 6.1 Exactness policy [A1, A4, B1]

Concurrent and solo run **two arithmetic paths** in S2:
- concurrent: packed K64j non-causal 0x27, 16-row tickets;
- solo: one live user, so the sequential 4-row engine: `SerialAttentionReader`, one native causal B1 call per row, 12 heads, a half-tile Q (`attention_batch.py:89-115`; `packed_verifier.py:396`; `model_batch.py:442`).

Rev 1 declared every reproduced concurrent-vs-solo divergence NOT COMPARABLE. That made the matrix unable to fail a deterministic packed-path error below C: a wrong word at some family reproduces, so it would read NOT COMPARABLE and pass. It also relaxed the user's standing default (MEM goal-c2-serving.md:35) without asking. Rev 2 replaces it.

**The policy, decided by CB2a K2:**

| K2 (CB2a) | Concurrent vs solo (M6-M10) | Same-path oracles (decisive in every case) |
|---|---|---|
| **PASS**: every K2 row bitwise equal, the half-tile shape included | **Strict, today's**: IDENTICAL, or reproduced DIVERGED = **FAIL** (`real_text_compare.py:427`). UNSTABLE blocks S2 exit until explained. NOT_COMPARABLE arises only from differing arithmetic flags (`:301-302`) and blocks exit until its record exists. | G3 at C (M3-M4); G3b at 4352 and 16640 (M5); the extent audit on every packed round of every S2 gate arm |
| **FAIL**: any K2 row differs | S2 stops after CB2a. **User decision D-c** (§5 first row). Only D-c(i) turns on the rev 1 classification, and then the permuted arm is required with ≥ 2 SAME_PATH users. | As above, plus the permuted arm under D-c(i) |

**Why the strict policy is plausible.** The split for a native row at p ≥ 128 equals the extent split at `cur_pos = E−1` (both are `nearest_n(p+1, 256) = E`, README:53-58), and cores per head are 16 for B ≤ 3 on both (README:61-62). What remains is the causal writer's generated mask against the provided one (same bits, README:120-121) and the half-tile Q. Agreement at C is empirical and short: v177 matched v158 over 4 × 256 tokens, and C2 matched v160 (PLAN:535-537 (c)). K2 decides it.

**The second channel, ticket width** (§1.4 #8): the forced-cap arm (M4) runs the same packed path with the session cap forced to 8 against uncapped. IDENTICAL confirms that commit granularity does not change the text. A divergence there FAILS, since both arms are the same path.

**Path records** (W11) are still collected per user and round: (ticket position, path P/S, committed prefix). They explain a divergence, and they count SAME_PATH users in a permuted arm.
